# Agent Working Agreement

1) **Test baseline FIRST**: Before making ANY code changes, run `npm test` to establish a baseline. Record the number of passing tests. This is your responsibility, not negotiable.

2) **Test after EVERY significant change**: Run `npm test` after each major change. If tests that were passing now fail, YOUR changes broke them. Fix them immediately.

3) **Read the artifacts first**: Before starting any task, read the rulebook (`rolling-fiefdoms-rulebook.pdf`) and the player sheet (`rolling-fiefdoms-player-sheet.webp`) to establish the rules context. Then read the existing code (notably `app.js`, `rules.js`, and tests) to understand current logic and gaps.

4) **Rule changes require tests**: Any change that affects rules, scoring, or turn flow must include a new test or an update to existing tests. Do not leave rule logic untested.

6) **Handle errors gracefully**: Code should defensively handle undefined/null and unexpected states without crashing.

7) **Keep the log useful**: Maintain a clear, chronological log (newest first) to help users trace actions.

8) **Do not bypass rules**: Do not introduce shortcuts that skip or relax rule requirements without explicit direction; align behavior with the rulebook.

10) **Document clarifications**: Any clarification provided by the user and not documented in the code or in the rulebook should be documented in the Appendix: Current clarifications.

11) **No duplicate entries in CSS**: CSS files should not have duplicates entries that can override each other, ie each selector should have only a unique CSS style entry

12) **Clean up temporary files**: After completing a task remove any temporary file generated, also remove any screenshot shared by the user for debugging or illustrating a request.

## Appendix: Current clarifications

- Guided scrolling on narrow screens (`<=1100px`, see `app/scroll-guide.js`'s `guideTo()`): on each step transition (building/guild chosen, population placement pending, forfeit/pestilence forced; building choice itself happens in the narrow-screen picker inside the action bar, so there is no scroll to the Buildings panel) the viewport auto-scrolls to the next relevant control if it isn't fully visible below the sticky `.action-bar`, honoring `prefers-reduced-motion`. Triggered only on step changes (tracked via `lastGuidedStep` in `app/app.js`, reset on roll), not on every re-render. Pending plots dim other `.cell.highlight` candidates (`opacity: .45`) via a `:has()` selector while still letting the player tap them to move the pending plot.
- Windrose faces replace previous paired faces; they are wild for location (1–5), must stay in the location pair, and count as 0 during pestilence.
- Dice locking: after selecting a building or resolving pestilence/forfeit, dice are locked and should remain visible/grey until the next roll; location/build previews must persist during the lock.
- Mid-game scoring: zero-requirement buildings (Cottage, Springhouse) and vagrants can score during play; worker-requiring buildings only score after activation at game end.
- Adjacency is cardinal-only, matching the printed square grid.
- PWA behavior: a cache-first service worker (cache name `rf-cache-v1`) precaches the core shell (HTML, JS, CSS, fonts, images including `assets/img/forfeit.svg`) and serves navigation offline. Bump the cache version when changing core assets. Manifest icon uses `assets/img/forfeit.svg`.
- Influence application: Can be applied to any die with a resolved numeric value (1-5) if: (1) influence points are available, (2) no other die currently has influence applied, (3) not during pestilence. This includes N dice and X dice with resolved values. When influence is applied to adjust an X die's value, that die is included in location pair calculations via `state.influenceTarget` in `game-state.js` to properly enable rescue from forfeit situations.
- Narrow-screen building picker: on screens ≤1100px, where the Buildings/Guilds sheet overlay hitboxes are too small to tap, the current building/guild choice is mirrored as touch-sized buttons (`#buildingPicker`, `.building-pick`) in the sticky action bar (`renderBuildingPicker()` in `app/app.js`), reusing the overlay's own `.building-hit`/`.guild-hit` `available`/`selected` state and delegating clicks to the matching hitbox; building/guild rules are unchanged.
- Touch confirm step: on coarse-pointer (touch) devices, plot, forfeit and population placements require a Confirm step (with Change plot/Change square to back out) before committing; mouse devices commit immediately on click as before. Game rules and resulting state are unchanged either way (`app/confirm-step.js`'s `needsConfirmStep()`).
- Action controls (roll, influence, swap, confirm, building picker) live in the action bar only; the Pair & Build panel (`#locDicePreview` / `#buildDicePreview`) is a read-only preview of dice faces/role grouping with no influence controls or click handlers. Influence is adjusted via a single stepper row in the action bar (`#influenceStepper`, at all widths), not per-die controls; each eligible die in `#diceView` shows a small ± badge (`.influence-target-btn`) to choose which die the stepper targets, without changing that die's location/build selection.
- Fixed-height action bar: `.action-bar` has a single fixed height per breakpoint (`--ab-h`, via `height: var(--ab-h)`) so actions never shift the page, and its slots are vertically centered as a group (`display: flex; flex-direction: column; justify-content: center`, or `align-content: center` on the short-landscape CSS-grid variant). Slots: the banner (`max-height: var(--ab-banner-max)`, clamped to 2 lines — or tall enough for its 44px inline action button on coarse pointers — 1 line on short-landscape, text centered, overflow hidden), the main row (`.action-bar-controls`: dice, swap, roll/finish/new-game, badges; fixed `--ab-main-h`; `flex-wrap: nowrap` with `overflow-x: auto` as a last resort), and an aux row (`.action-bar-aux`, a wrapper in `index.html` holding `#confirmPlotBtn`/`#cancelPlotBtn`, `#buildingPicker`, and `#influenceStepper` on one line). This two-row structure (banner on its own centred row, the dice row centred below it) is shared at ALL widths — including desktop (`min-width: 1101px`) — except short landscape (`max-height: 500px`, which keeps its own compact single CSS-grid row with the aux content inline). At every width covered by the shared `@media not (max-height: 500px)` block, `--ab-h` only covers the banner + main row, and `.action-bar-aux` is an absolutely positioned "drawer" (`position: absolute; top: calc(100% - 12px)` tucked under the sticky bar, as wide as its content and centred, rows stacked: influence stepper, then building picker, then Confirm/Change; the banner slot has a fixed height so the dice row and drawer stay put, same `--panel` background, border + shadow, same `z-index`) that overlays the sheet below it rather than pushing it down, sliding/fading open and closed (`transform`/`opacity`/`visibility` with a `visibility` transition delay so it only becomes non-interactive once the close animation finishes; instant under `prefers-reduced-motion: reduce`) instead of toggling `display: none`, centred horizontally with 44px-min buttons on coarse pointers. On desktop, `#buildingPicker` is never shown (`.building-picker { display: none }` outside `≤1100px`) even though JS may remove its `[hidden]` attribute, so a second, later `@media (min-width: 1101px)` block overrides the drawer's open/closed check to ignore the picker (open only when `#confirmPlotBtn` or `#influenceStepper` is visible) and bumps `--ab-banner-line-h`/the banner's `font-size` up (22px / 32px line-height) with `--ab-banner-max: 48px` (desktop prompts fit on one line; 48px leaves room for the 36px inline button) for a resulting `--ab-h` of 132px (48px banner + 76px main row + 8px); the pre-roll "hide the empty dice row" rule uses `visibility: hidden` (not `display: none`) there so the fixed height never jumps. Guided scrolling (`app/scroll-guide.js`'s `guideTo()`) accounts for the open drawer by treating the obstruction bottom as `max(action-bar bottom, visible action-bar-aux bottom)`. Heights are driven by CSS custom properties on `.action-bar` (`--ab-banner-max`, `--ab-banner-line-h`, `--ab-main-h`, `--ab-aux-h`, `--ab-h`), overridden per breakpoint (`pointer: coarse`, `min-width: 1101px`, `max-height: 500px`, which also merges the main and aux rows into one CSS-grid row to keep short-landscape bars compact, with its own `--ab-h` and a `(max-height: 500px) and (pointer: coarse)` override growing the banner row so the inline action button isn't clipped).
- Inline banner action buttons: banner prompts that reference an action button (e.g. "Press [Roll Dice] to start your turn.") render that button inline as a real, clickable control (`formatButtonLabelHtml(label, targetId)` + the delegated click handler on `#actionBanner` in `app/app.js`, `syncInlineActionButtons()` in `app/ui-feedback.js` keeps it enabled/disabled in sync with its target) at all widths. The standalone duplicate (`#rollBtn` / `#finishActivation`) is hidden at all widths while the prompt shows its inline twin.

- Autoplay mode & E2E tool: `app/autoplay.js` is a player-like autoplay driver and interactive test controller. It can be invoked directly in the browser by appending `?autoplay=N` to the URL, where `N` is a **game index** (`0` = normal game, `1`–`8` = challenge by 1-based index into `CHALLENGE_ORDER`). This skips the challenge-picker modal and starts the selected game directly. Speed is controlled independently via `?speed=fast|instant|max|<ms>` (e.g. `?autoplay=0&speed=fast`). The legacy speed-only forms (`?autoplay=fast`, `?autoplay=instant`, `?autoplay=loop`) still work when the value is not a digit. The HUD exposes pause/resume, step, speed buttons and a loop toggle; `window.rfAutoplay` holds the active session. It automatically enables `window.__RF_ENABLE_TEST_HOOKS__ = true` and supports both touch and desktop layouts. It can also still be used programmatically in headless browser reviews (`chrome-devtools` MCP `evaluate_script` or node/vitest tests) via `startAutoplaySession()` / `autoplayStep()`.
